## 第一轮优化

先完成 T1 内的证据闭环：固定 SDPA/BF16/KV cache，扫描 batch 和上下文长度；对混合长度数据分别测原顺序与 `--length-bucket`，记录 padding 浪费；再做 `use_cache=True/False` 消融，并在开发模式拆分 prefill/decode。每次只改一个变量，保留 commit、参数、正确性结果和至少五次原始性能数据。

只有当 T1 结果稳定后，再做 T2 的 FlashAttention、KV Cache layout、RMSNorm/MLP 融合。T1 的长度排序减少的是输入补齐浪费，不等于连续批处理或 PagedAttention。

## T4 并行线

T4 可以从现在开始独立推进，入口是 `kernels/`。先在目标 DCU 镜像完成 Triton 正确性和单算子 benchmark，再用可恢复的 vLLM patch 验证 RMSNorm、SiluAndMul 和 QKV+RoPE 的端到端收益。详细验收门槛见 `docs/T4实施计划.md`；Colab T4 的结果只用于验证算法方向，不能替代 DCU 数据。

## 第二轮优化

接入 vLLM 的连续批处理和 PagedAttention，比较并发数、最大 batch、KV block 大小和上下文长度。只在 profiling 证明存在热点后写 HIP kernel。
