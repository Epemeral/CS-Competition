# T4 学习资料与落地路线

Datawhale 的[大模型算法实战教程](https://datawhalechina.github.io/llm-algo-leetcode/)可以作为 T4 的学习入口，但它是教程资料，不是比赛规则。Part 3 默认以 CUDA/NVIDIA 为例，算子公式和实验方法可以复用，性能结论必须在 AMDGPU/DCU 重新测量。

## 推荐顺序

| 顺序 | Datawhale 内容 | 在本仓库的对应位置 | 用途 |
| --- | --- | --- | --- |
| 1 | [Fused RMSNorm](https://datawhalechina.github.io/llm-algo-leetcode/03_Triton_Kernels/03_Triton_Fused_RMSNorm.html) | `kernels/src/triton_kernels.py` | 学习行归约、mask、数值稳定性 |
| 2 | [Fused SwiGLU](https://datawhalechina.github.io/llm-algo-leetcode/03_Triton_Kernels/02_Triton_Fused_SwiGLU.html) | `swiglu`、`silu_and_mul_triton` | 学习逐元素融合和 block 选择 |
| 3 | [Autotune and Profiling](https://datawhalechina.github.io/llm-algo-leetcode/03_Triton_Kernels/05_Triton_Autotune_and_Profiling.html) | `kernels/benchmarks` | 设计 shape 扫描、warmup 和中位数 |
| 4 | [Fused RoPE](https://datawhalechina.github.io/llm-algo-leetcode/03_Triton_Kernels/07_Triton_Fused_RoPE.html) | `rope`、`qkv_split_rope` | 学习布局和位置编码融合 |
| 5 | [FlashAttention](https://datawhalechina.github.io/llm-algo-leetcode/03_Triton_Kernels/08_Triton_Flash_Attention.html) | 后续 attention 实验 | 需要 mask、数值稳定和端到端验证 |
| 6 | [PagedAttention](https://datawhalechina.github.io/llm-algo-leetcode/03_Triton_Kernels/09_Triton_PagedAttention.html) | 后续 vLLM/KV cache 实验 | 需要真实 block table 和请求级 benchmark |
| 7 | [Quantization](https://datawhalechina.github.io/llm-algo-leetcode/03_Triton_Kernels/10_Triton_Quantization.html) | 后续量化实验 | 需要校准、误差报告和 DCU 后端支持 |

## 当前可直接使用的结论

1. 先做 RMSNorm、Add+RMSNorm 和 SiLU+Mul 的正确性与单算子基准。
2. Qwen2.5-7B 是 GQA：Q 头 28、KV 头 4、head_dim 128。QKV 输出维度是 4608，不能按三份相同 head 数切分。
3. `rmsnorm_v2` 只适合大特征维度；3584 维应优先走单遍路径。是否改变 `block_cap` 必须以 DCU 结果为准。
4. 只有当 component share 或 profiler 证明算子占比足够高，才值得继续做端到端接入。

## T4 验收记录

每次实验保存：设备名、PyTorch/Triton/DTK 版本、git commit、dtype、batch/token shape、warmup、rep、编译是否计入、原始 JSON。NVIDIA T4 和海光 DCU 的结果分开写，不能互相代替。
