# T1 学习指南：先跑通，再测准

## 赛题目标

固定模型为 `Qwen2.5-7B-Instruct`，在海光 DCU 上完成推理系统优化。T1 的第一目标是跑通官方 `baseline.py` 和 `evaluate.py`，并保证贪心解码逐 token 一致。当前仓库中的 `baseline.py` 是账号发放前的准备版本，不能替代组委会脚本，也不能产生正式成绩。

## 需要掌握的概念

- **prefill**：把整段输入送入模型，计算并缓存已有 token 的 K/V。
- **decode**：逐 token 生成；每一步复用 KV Cache，避免重复计算历史上下文。
- **KV Cache**：每层保存 Key/Value，换取显存空间和更低的 decode 计算量。
- **贪心解码**：每一步选择最大 logit 的 token。T1 比较 token ID，不能只比较解码后的字符串。
- **吞吐**：并发请求在单位时间生成的 token 数，是比赛性能项的核心。
- **预热与同步**：GPU 测量前先预热；计时前后同步设备，否则异步执行会导致结果失真。

## 本地练习

本地没有 DCU 时，用 tiny 模式验证数据格式、批处理、EOS 截断、重复运行确定性和结果 JSON：

```powershell
.venv/Scripts/python baseline.py --tiny --output results/tiny-run.json
.venv/Scripts/python -m unittest discover -s tests -v
```

拿到远程环境后，保留相同命令结构，改用预置模型和 DCU 设备（具体设备参数以组委会镜像为准）：

```bash
python baseline.py --model Qwen/Qwen2.5-7B-Instruct --device cuda \
  --dtype float16 --data official/correctness.jsonl --output results/t1-baseline.json
```

## 常见错误

不要在 CPU 结果上推断 DCU 性能；不要把 tokenizer、模型加载和 GPU 异步时间混入或排除得不一致；不要改变 prompt 模板、EOS、最大生成长度或随机采样参数后再比较；不要把本地 tiny 模式的结果作为比赛成绩。

## 建议阅读顺序

先读 Transformers 的 `generate` 和 Qwen2 模型实现，再读 vLLM 的请求调度与 PagedAttention，最后根据 profiling 结果学习 HIP kernel。QwenLM/Qwen 仓库是旧版 Qwen 代码，README 已说明它不再活跃维护；赛题指定的 Qwen2.5 应以当前 Transformers/Qwen2 实现为准。
